# Android ARM64 qualification protocol — Leo v0.28.0

**Status:** qualification plan and automated packaging checks are prepared; no Android build or physical-device result is claimed by this document.

## 1. Required build environment

The qualification runner must use the versions pinned by the workspace:

- Flutter `3.47.1` (stable) and its bundled Dart SDK.
- Rust `1.100.0`, with `aarch64-linux-android` target.
- Flutter Rust Bridge generator `2.13.0`.
- Java 17.
- Android SDK platform 36 and Build Tools `36.0.0`; Android NDK `30.0.16248370`; CMake `3.22.1`; and Ninja.
- The llama.cpp source revision recorded in `scripts/build_android_native.sh`; a different checkout is a hard failure.
- App compile SDK 36, Android ABI `arm64-v8a`, minimum API 28.

The build must execute `scripts/build_android_app.sh` with `LEO_ANDROID_BUILD_MODE=both`. This creates debug and release-mode test APKs from the same pinned native adapter and validates both artifacts. The generated runner uses its test signing configuration; neither APK is a production-signed release. Production signing belongs to the later RELEASE cycle.

## 2. Automated gates

The CI qualification job must pass all of the following:

1. Version, release-channel and immutable-source checks.
2. Python architecture/source-contract tests.
3. Dart format, Flutter analyze and Flutter tests.
4. Rust format, workspace tests and Clippy with warnings denied.
5. Flutter Rust Bridge generation with no unexplained generated-code drift; commit `apps/leo_app/pubspec.lock` and workspace `Cargo.lock` generated by the pinned toolchains before qualification so dependency resolution is reproducible.
6. Android ARM64 Rust compilation and pinned NDK/CMake/llama.cpp native adapter build.
7. Native C ABI export checks and Android ELF checks.
8. Generated runner validation: application ID `ai.leo.leo_app`, minSdk 28, backup disabled, SharedPreferences excluded from cloud and device transfer, and no broad storage/package-visibility permissions.
9. Debug and release-mode APK ZIP integrity; required `libleo_llama_backend.so` and `libc++_shared.so`; every packaged `.so` must be 64-bit little-endian AArch64; no unexpected ABI; no bundled GGUF/ONNX/voice/model weights.
10. Write SHA-256 manifests for both APKs and the native adapter; upload both APKs and both checksum manifests as CI artifacts.

A passing static APK verifier is not a substitute for installing and running the APK.

## 3. Physical-device matrix

Test at least two supported ARM64 Android devices with materially different memory/storage capacity. For each device, record:

- Manufacturer/model, Android version/API level, OS build and security patch.
- CPU ABI, RAM, available storage and battery/power state.
- APK filename, SHA-256, app version/build, and whether it is a clean install or upgrade.
- GGUF filename checksum, model architecture/quantization, model file size, context length and selected CPU threads.
- Voice-pack manifest/checksum and selected ASR/TTS configuration when voice tests are run.

Do not place chat prompts, model output, personal contact details, file contents, memory contents, passphrases, or keys into shared CI/device logs. Redact account names and personal paths from diagnostic attachments.

## 4. Required functional checks

| Area | Test | Pass condition |
|---|---|---|
| Install/start | Clean install, first launch, restart, upgrade from the previous Alpha APK, then uninstall | App opens without a fatal exception; expected local-data migration and uninstall behavior is documented. |
| Offline | Enable airplane mode before launch and keep it enabled | Core UI, local model import and local inference do not require a network service. Optional network functions fail clearly and do not block the local workflow. |
| Model import | Import a valid ARM64-device GGUF through the system document picker; repeat with a truncated, wrong-hash and invalid-header file | Valid model is copied/registered and checksum-verified; invalid files are rejected without corrupting the catalogue. No broad storage permission is requested. |
| Inference | Load model, generate short/long Arabic and English responses, use mixed Arabic/English and code, then unload/reload | Correct local runtime is reported; output streams; model lifecycle returns to idle; no crash or stuck native session. |
| Context | Run a long history with tool cycles and an oversized current request | Whole-turn compaction notice appears; system policy and latest complete turn remain; oversized current input fails visibly rather than fabricating a response. |
| Cancellation | Stop before native start, during memory preflight, prompt evaluation, decode and just before completion | Only the active request is stopped; no late Stop cancels the next request; cancelled output does not continue after its terminal event. |
| Memory | Create/review/activate a memory, restart, search, edit, rotate key, back up, import with correct/wrong passphrase, erase | Content is retained only as expected; imported memories remain pending/inactive; wrong passphrase/tampering fail closed; erase removes DB sidecars and secure key entries. |
| Secure storage | Revoke screen lock where applicable, clear app data, reinstall and test upgrade/restore behavior | Missing/unreadable platform keys produce an explicit recovery path; no plaintext fallback or silent key regeneration over unreadable encrypted data. |
| Agent recovery | Start a multi-step task, allow a safe completed step, interrupt/restart, resume, and separately test a pending external action | Successful checkpoints are not rerun; pending external actions are not replayed automatically and require user review. |
| Skills | Import, review, activate, run, interrupt, recover and mark a skill run reviewed | Invalid or unapproved skills cannot run; every external action still passes Capability Hub approval. |
| Voice | Import local voice packs, capture short Arabic/English speech, synthesize speech, background/foreground and revoke microphone permission | ASR/TTS work offline; permission denial is handled; recording stops on route/lifecycle cancellation; no background listening. |
| OS capabilities | Test contacts consent, SAF file/folder selection, selected-document opening, dialer, mail/SMS drafts, calendar draft, clipboard write, URL/app handoff | Each operation is scoped, shown to the user and handled by the target OS app; denial/revocation is respected; no direct send/call or background write occurs. |
| Low memory | Repeat model load/generation under memory pressure and with free memory below the 96 MiB preflight reserve | Leo reports a clear preflight failure without crashing or corrupting the loaded model/session. Record device free-memory evidence because system-wide MemAvailable is not identical to the app's effective limit. |
| Background/lifecycle | Background during generation; navigate away during generation; rotate screen; lock/unlock; low-storage scenario | No silent auto-resume, duplicate action or stale UI update; partial visible text and terminal state remain consistent. |

In addition to these cases, run the runtime resilience and benchmark procedure in `docs/testing/RUNTIME_RESILIENCE_AND_BENCHMARKS.md` on each device/model configuration.

## 5. Acceptance and evidence

Android qualification is complete only when:

- All automated CI gates above pass on the pinned runner.
- Every mandatory physical-device case has a recorded pass/fail result for both devices, with reproducible evidence and defect references for failures.
- APK SHA-256 values match the CI artifacts used on devices.
- No unresolved release-blocking crash, data-loss, permission, privacy, offline, lifecycle or native-runtime defect remains.
- Secure-storage, memory backup/restore, permission-revocation and offline behavior have been reviewed explicitly.

Store a redacted qualification report and CI run link under `docs/audit/` before marking `v0.28.0` complete. Do not advance to Windows qualification (`v0.29.0`) by silently treating an incomplete Android gate as passed.
