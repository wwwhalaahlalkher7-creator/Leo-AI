### Local-memory native dependency

- `leo-memory` uses `rusqlite = 0.43.0` with the `bundled` feature; SQLite is compiled into the target build rather than requiring a separately installed SQLite DLL/shared library.
- Android builds therefore require the pinned NDK C compiler; Windows builds require the MSVC C/C++ build tools already present in the Windows runner.
- The `rusqlite` wrapper is MIT-licensed and the bundled SQLite core is public domain; notices are retained in `licenses/`.

The Windows adapter uses a strict web scheme allowlist (HTTP/HTTPS), dedicated mail and telephone handoffs, and a restricted registered-app target pattern.


### Structured Tool Execution Gateway v0.12.0 additions

| Component | Behavior | Local verification |
|---|---|---|
| `tool_call_protocol.dart` | Versioned one-call envelope, 16 KiB UTF-8 limit, exact argument schemas, allowlisted tools and input bounds | Dart unit test authored; not run locally because Dart is unavailable; Python source contract checks run |
| `ToolExecutionGateway` | Typed dispatch through `CapabilityHubService` only; maximum three sequential calls per user turn; bounded untrusted results | Python static/contract suite; Flutter integration tests and platform smoke tests pending |
| Chat integration | Suppresses raw tool-call blocks, sends tool results as untrusted `tool` messages, and avoids persisting raw payloads/results in the user transcript | Source contract checks; Flutter runtime test pending |
| Tool audit | App-private metadata-only history, maximum 100 records; no user arguments or operation content | Source/privacy contract checks; device storage review pending |

The gateway does not expose shell/PowerShell, arbitrary process execution, file deletion/move/rename, direct email/SMS sending, direct phone calls, microphone capture or general UI automation. Alpha v0.22.0 adds one tightly scoped `workspace.write_file` handoff for `file_operator`: create or replace exactly one UTF-8 text file directly in a folder explicitly selected by the user, bounded to 16 KiB and 10,000 Unicode code points, with a before/after diff and a separate approval for every write. Nested paths, directory creation and bulk writes remain disabled. Android uses a short-lived Storage Access Framework tree grant and fails closed when the provider cannot stage/rename safely; Windows uses a folder picker, rejects reparse points, stages in the selected folder and verifies the final SHA-256. SAF and Windows still have a narrow external-writer race between final recheck and replacement. Email and SMS actions create drafts; phone actions open the dialer. Android-only contacts and SMS tools are blocked on Windows.

### Durable task checkpoint storage — v0.21.0

| Component | Version/requirement | Role | Platform/build notes |
|---|---|---|---|
| `flutter_secure_storage` | `^11.2.0` | OS-backed encrypted key/value storage for at most eight local agent checkpoints | Android default uses RSA-OAEP key wrapping and AES-GCM payload encryption; secure-storage SharedPreferences are excluded from backup/device transfer by the generated Android manifest rules. Windows requires the C++ ATL optional component in Visual Studio Build Tools. Plugin documents Android, Windows and other platform support; Leo only enables this store on its Android/Windows targets. |

The generated Android runner must be prepared with `scripts/prepare_android_runner.sh`; it sets `android:allowBackup="false"` and writes explicit SharedPreferences exclusions for cloud backup and device transfer. Do not enable application backup for the secure checkpoint preferences without designing a corresponding Keystore/key migration path. The secure store is a local recovery mechanism, not cross-device sync.

No directory creation, nested paths, delete/move/rename, shell, process execution or bulk writes. Platform filesystem race limitations remain documented in ADR-0027.


### Android qualification build gate preparation (2026-11-18)

- The generated app Gradle file and `scripts/build_android_native.sh` now both pin/check NDK `30.0.16248370`; CI explicitly installs Android SDK platform 36, Build Tools `36.0.0` and CMake `3.22.1`. The llama.cpp checkout revision, ARM64 ABI and API 28 target remain pinned.
- `scripts/verify_android_runner.py` validates the generated app ID, compile SDK 36, API 28 minimum, disabled backup, SharedPreferences cloud/device-transfer exclusions and restricted permissions.
- `scripts/verify_android_apk.py` validates APK archive integrity, required Leo/C++ native libraries, 64-bit AArch64 ELF headers for every native library, single-ABI packaging and no bundled local model/voice weights; the build emits SHA-256 manifests for the APKs and native libraries.
- CI now builds debug and release-mode ARM64 test APKs (the generated template uses its debug test key, not a production key) and uploads checksums. These checks are source-implemented; actual Flutter/NDK compilation and physical-device qualification remain pending. See `docs/testing/ANDROID_QUALIFICATION_PROTOCOL.md` and `docs/audit/ANDROID_QUALIFICATION_PREP_WORK_LOG.md`.
